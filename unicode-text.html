文字コードと Unicode

「1 文字」は何バイト？ 何文字？ —— 番号（コードポイント）と、そのバイト列（UTF-8 / UTF-16）を分けて考える

ざっくり言うと
  • Unicode は文字に番号（コードポイント、U+3042 など）を振る表。それをバイト列にする方法が UTF-8・UTF-16。「Unicode で保存」ではなく「UTF-8 で保存」が正しい言い方。
  • 「1 文字」には数え方が 4 つある：バイト数・UTF-16 の単位数（JS の length）・コードポイント数・見た目の文字数（書記素クラスタ）。絵文字や濁点でずれる。
  • 同じ見た目でも内部が違うことがある（「が」が 1 個か「か＋゛」の 2 個か）。比較・検索の前に正規化（NFC / NFKC）する。

UTF-162 か 4 バイト（2 バイト単位 1 つか 2 つ）JavaScript・Java・C#・Windows の文字列の単位（Java 9 以降は内部で Latin-1 も使うが、length() などは UTF-16 単位）

UTF-8 のしくみ

先頭バイトの上位ビットで「何バイトの文字か」がわかり、2 バイト目以降は必ず 10 で始まるので、途中から読んでも文字の切れ目を見つけられます。

正規化

Unicode には同じ見た目を表す方法が複数あります。比較・検索・重複チェックの前に、どちらかの形に揃えます。

形式やること例使う場面
NFC合成できるものは合成か＋゛ → が保存・比較の標準。Web はこれ
NFD分解できるものは分解が → か＋゛macOS 由来のファイル名で見かける
NFKC互換文字も統一して合成ｶﾞ → ガ、ＡＢＣ → ABC、① → 1、㈱ → (株)検索キー・ユーザー名の重複判定
NFKD互換文字も統一して分解あまり使わない
'が' === 'が'                        // false（見た目は同じ）
'が'.normalize('NFC') === 'が'       // true
'ﾃｽﾄＡ１'.normalize('NFKC')                // 'テストA1'

NFKC は情報を落とす（① と 1 の区別が消える）。元の文字列は NFC で保存し、検索用の列にだけ NFKC＋小文字化した値を持つ、と分けるのが安全。

実務の落とし穴

書いた側と読む側で符号化が違うと起きます。UTF-8 の「日本語」を Shift_JIS として読むと「譌･譛ｬ隱・」のようになる。

  • HTTP は Content-Type: text/html; charset=utf-8、HTML は <meta charset="UTF-8"> を先頭近くに
  • Excel 向けの CSV は、UTF-8 の BOM（先頭の EF BB BF）を付けないと Shift_JIS と判定されて化けることがある
  • 逆に、BOM 付きのファイルを読むと先頭に見えない文字が残り、最初の列名が一致しないことがある

MySQL の utf8（別名 utf8mb3）は1 文字 3 バイトまでしか扱えず、絵文字や 𠮷 が保存できない（エラーや欠落）。必ず utf8mb4 を使う。

VARCHAR(255) の 255 が「文字数」か「バイト数」かは DB によって違う。PostgreSQL・MySQL は文字数（コードポイント数）、Oracle の既定はバイト数。

「20 文字まで」の制限をどの数え方で判定するかを決める。JS の length で数えると、絵文字 1 つが 2 文字分以上（組み合わせた絵文字では 10 文字分を超えることもある）に数えられてしまう。

  • ユーザーに見せる上限 → 書記素クラスタで数える
  • DB・API の上限 → バイト数や DB の数え方に合わせて、サーバー側でも検証する
  • 途中で切るときは書記素の切れ目で切る（サロゲートペアの片方だけ残すと壊れる）

見た目が同じ別の文字（ホモグリフ）で偽装できる。キリル文字の「а」（U+0430）とラテン文字の「a」は見分けがつかない。

  • ドメイン名ではブラウザが混在を検知して xn-- で始まる Punycode 表示に切り替えることがある
  • ユーザー名は NFKC で正規化したうえで、使える文字の種類を絞る
  • 大文字小文字の変換は言語によって違う（トルコ語の i / İ）。ID の比較には言語に依存しない変換を使う

よくある誤解

Unicode は 1 文字 2 バイト

それは UTF-16 の、しかも U+FFFF までの文字の話。Unicode 自体は番号の表で、バイト数は符号化で決まる。UTF-8 なら 1〜4 バイト。

JS の length で文字数が数えられる

length は UTF-16 の単位数。絵文字や 𠮷 で増える。見た目の文字数は Intl.Segmenter で数える。

同じに見える文字列は === で一致する

合成済みか結合文字か、全角か半角かで別の文字列になる。比較前に正規化する。
