UI 更新の3つの方式

仮想 DOM / シグナル / コンパイラ — 「状態が変わったら、どこを書き換えるか」の解き方

ざっくり言うと
  • UI フレームワークの仕事は、状態が変わったときに、画面のどこを書き換えればいいかを突き止めること
  • 仮想 DOM は「全部作り直して差分を取る」、シグナルは「どの表示がどの値に依存しているかを記録しておく」、コンパイラは「ビルド時に更新コードを書き出しておく」
  • 3つは排他ではなく組み合わさる。Solid はシグナル＋コンパイラ、Vue は仮想 DOM ＋リアクティブ、Svelte 5 はコンパイラ＋シグナル

同じ操作で、何が動くか

ヘッダー・カウンター・リストを持つ小さなアプリで、ボタンを押してカウントを 1 増やす（count は App が持ち、Counter に渡して表示している）。各方式で「どこが再実行され、どこが書き換わるか」を比べる。

最終的に書き換わる DOM はどれもテキスト1つで同じ。違うのは、そこにたどり着くまでの仕事量。仮想 DOM は「作り直して比べる」分の計算をし、シグナルは記録済みの依存関係をたどるだけで済む。

方式1：仮想 DOM

状態が変わると、コンポーネント関数を実行して「画面がこうあるべき」という軽い JS オブジェクトの木（仮想 DOM）を作り直す。前回の木と比べ（diff）、違う部分だけを本物の DOM に反映する（patch）。

div
h1 "Todo"
p
"count: 0"
ul（3件）
比較 →
div
h1 "Todo"
p
"count: 1"
ul（3件）

強み：コンポーネントは「状態を受け取って UI を返す普通の関数」として書ける。いつ・何回実行されても結果が同じになるように書けば、更新の仕組みを意識しなくていい。

弱み：変化と関係ない部分も毎回作り直して比べる。大きな木では無駄が増えるので、memo などで「ここは再実行しなくていい」と教える必要があった（React Compiler はそれを自動化する）。

方式2：シグナル（細粒度リアクティブ）

値をシグナルという入れ物に入れる。シグナルを読んだ処理を自動で記録しておき、シグナルに書いたときには、記録された処理だけを再実行する。

countsignal→ doubledcomputed→ 表示更新effect

仕組みは意外と小さい。核心部分だけ書くとこうなる。

let current = null;                  // いま実行中の effect

function signal(value) {
  const subs = new Set();            // この値を読んだ effect の一覧
  return {
    get() {
      if (current) subs.add(current); // 読まれたら「購読者」として記録
      return value;
    },
    set(v) {
      value = v;
      subs.forEach(fn => fn());       // 書かれたら購読者だけ再実行
    },
  };
}

function effect(fn) {
  const run = () => { current = run; fn(); current = null; };
  run();
}

// 使い方
const count = signal(0);
effect(() => { textNode.data = count.get(); }); // このテキストだけが count に依存
count.set(1);                                   // → このテキストだけ書き換わる

強み：変化した値に依存する場所だけが動く。コンポーネント全体の再実行も、差分計算もない。

弱み：「読んだ瞬間に記録する」仕組みなので、値を変数に取り出してしまうと追跡が切れるといった独特のルールがある（Solid の props の分割代入など）。

方式3：コンパイラ

テンプレートや JSX をビルド時に解析し、「この値が変わったらこの DOM ノードをこう書き換える」という専用コードを生成する。実行時に汎用の差分アルゴリズムを持たなくていい。

書くコード 
<p>count: {count}</p>
生成されるコード（イメージ） 
const p = template('<p>count: </p>');
const text = p.firstChild.nextSibling;
effect(() => { text.data = count(); });

コンパイラは単独の方式というより、シグナルと組み合わせて「どのノードに effect を張るか」を事前に決める役で使われることが多い。React Compiler は少し違い、再実行モデルはそのままで、メモ化を自動挿入して無駄な再実行を減らす。

よくある誤解

✕ 「仮想 DOM は本物の DOM より速い」

○ 仮想 DOM は最終的に本物の DOM 操作を行うので、それ自体が速さを生むわけではない。価値は「宣言的に書いても、まあまあ速い」こと。最適な手書きの DOM 操作より速くはならない。

✕ 「シグナルは新しい発明」

○ Knockout.js（2010年）や MobX など、昔からある考え方。Solid が JSX と組み合わせて再注目させ、今は Angular、Vue、Svelte、Preact も取り入れている。JavaScript の標準に入れる提案（TC39 Signals）も出ている。

✕ 「仮想 DOM は時代遅れで遅い」

○ 多くのアプリでは差分計算はボトルネックにならない。React Native のように DOM 以外に描画する場合は、中間表現があることが強みにもなる。
