コントラスト比・ダークモード・OKLCH —— 「なんとなく」で選ばないための 3 点

**ざっくり言うと**

- 文字と背景の **コントラスト比は 4.5:1 以上** （大きな文字・アイコン・入力欄の枠は 3:1 以上）。見た目の好みより先にこれを満たす。
- ダークモードは「白黒反転」ではない。 **真っ黒・真っ白を避け、アクセントは明るく彩度控えめ** に作り直し、重なりは「明るさ」で表す。
- パレットは **OKLCH** で作ると、色相を変えても「同じ明るさ」に見える段階がそろう。HSL の L は人間の見た目の明るさと一致しない。

## コントラスト比

2 色の **相対輝度** （人の目に感じる明るさに近づけた値）の比で、1:1（同じ色）〜 21:1（白と黒）。アクセシビリティ基準 WCAG の AA レベルが実務の目安です。

| 対象 | AA（目安） | AAA |
| --- | --- | --- |
| 本文などの通常の文字 | 4.5 : 1 | 7 : 1 |
| 大きな文字（約 24px 以上、太字なら約 18.66px 以上） | 3 : 1 | 4.5 : 1 |
| アイコン・入力欄の枠・フォーカスリングなど UI 部品 | 3 : 1 | —（フォーカス表示は 2.4.13 で、フォーカス前後の差 3:1 以上） |
| 無効化 (disabled) の部品・ロゴ・飾り | 基準の対象外 |  |

## HSL ではなく OKLCH を使う理由

下の 2 段は、どちらも「明度を同じ値に固定して色相だけ回した」色です。HSL は数値上同じでも、黄色は明るく青は暗く見えます。OKLCH は **人の見え方に合わせた色空間** なので、明るさがそろって見えます。

hsl(H 90% 50%) — L はすべて 50%

oklch(0.7 0.15 H) — L はすべて 0.7

HSL 段では黄緑・緑の上の黒文字はとても読みやすいが、青の上ではほぼ読めない（同じ L=50% なのにコントラスト比が約 14:1 から約 2.5:1 まで開く）。OKLCH 段は同じ黒文字がどの色でも同程度に読める ＝ 明度を固定すれば **コントラストもほぼ固定** できる。

### OKLCH の読み方

**L** 明度 Lightness

0（黒）〜 1（白）。見た目の明るさにほぼ比例。

**C** 彩度 Chroma

0（灰色）〜 0.3 前後。上限は色相と明度で変わる。

**H** 色相 Hue

0〜360 の角度。約 25 赤・90 黄・145 緑・250 青。

H 250

C 0.13

L だけを 0.95 → 0.25 まで、ほぼ等間隔（約 0.07〜0.10 刻み）に下げた 9 段階のパレット。色相を変えても段ごとの明るさがそろうので、 `--blue-500` と `--green-500` を入れ替えても文字のコントラストが崩れにくい。

```
/* パレット：L だけを変える */
--blue-100: oklch(0.95 0.03 250);
--blue-500: oklch(0.62 0.15 250);
--blue-900: oklch(0.30 0.08 250);

/* ホバー色を元の色から計算（相対カラー構文） */
.button:hover { background: oklch(from var(--accent) calc(l - 0.08) c h); }

/* 混ぜるときも OKLCH で（途中がくすみにくい） */
.badge { background: color-mix(in oklch, var(--accent) 15%, transparent); }
```

C を上げすぎると、普通のディスプレイ（sRGB）で表示できない色になり、ブラウザが近い色に丸める。広色域（Display P3）の画面ではより鮮やかに出る。

（元のページで操作できます → https://memo.taka1156.site/color-basics.html#oklch-syntax）

## ダークモードの色の作り方

ライトの色を反転しただけだと、まぶしく、ギラつき、階層がわからなくなります。

✕ 反転しただけ 純黒の背景に純白の文字。アクセントもライトと同じ濃い青。

カード（背景と区別できない）

ボタン

○ 作り直した 少し青みのある暗色の背景、少し落とした白の文字。アクセントは明るく。

カード（一段明るい面で浮かせる）

ボタン

| ポイント | 理由 |
| --- | --- |
| 背景は純黒を避ける | 純白の文字との差が大きすぎて文字がにじんで見える（ハレーション）。#0a0e14 程度の暗色に。 |
| 重なりは「明るさ」で表す | 暗い背景では影がほとんど見えない。上にあるものほど少し明るい面にする。 |
| アクセントは明るく・彩度控えめに | ライト用の濃い色は暗い背景に沈む。L を上げ、鮮やかすぎる色は C を少し下げる。 |
| コントラストは測り直す | ライトで 4.5:1 を満たしても、ダークの組み合わせは別物。両方でチェックする。 |

実装はトークンのセマンティック層を差し替えるのが基本 → [デザイントークン](https://memo.taka1156.site/md/design-tokens.md)

## 色だけで意味を伝えない

色の見え方には個人差があり、日本人男性では約 20 人に 1 人が赤と緑を見分けにくいとされます。エラー・成功などは **色＋形（アイコン）＋文字** で伝えます。

## よくある誤解

✗ 誤解: HSL の L をそろえれば同じ明るさになる

✓ 正しくは: HSL の L は計算上の値で、人の見え方とは一致しない。同じ 50% でも黄色と青では見た目の明るさが大きく違う。OKLCH の L はほぼ見た目どおり。

✗ 誤解: コントラストは高ければ高いほど良い

✓ 正しくは: 基準は「最低ライン」。ダークモードで純黒 × 純白にすると眩しさやにじみで逆に読みにくくなる。基準を満たした上で少し抑える。

✗ 誤解: ブランド色の上の白文字なら読める

✓ 正しくは: オレンジや黄緑など明るいブランド色は、白文字だと 3:1 にも届かないことがある。チェッカーで確かめ、ダメなら暗い文字にするか色を暗くする。

✗ 誤解: ダークモードはフィルターで反転すれば作れる

✓ 正しくは: 画像やブランド色まで反転してしまい、影や重なりの表現も崩れる。色はダーク用にトークンを作り直す。
