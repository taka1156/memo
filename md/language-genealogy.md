## 関係の 3 種類

### 派生（直系）

方言・後継・改名など、言語そのものが受け継がれている関係。

例: Caml Light → OCaml → F#、BCPL → B → C

### 影響

設計者がアイデアや機能を借りた関係。多くの親を持てる。

例: Haskell の型クラス → Rust のトレイト

### 実装

その言語で処理系（コンパイラ）を書いた関係。設計上の親とは別物。

例: Rust の初代コンパイラ rustboot は OCaml 製

## よくある誤解

✗ 誤解: Rust は C++ の子孫

✓ 正しくは: 波括弧の構文やメモリモデルは C++ 寄りだが、型システム（enum・match・型推論）は ML 系。どちらか一方の子ではなく、両方の血を引く。

✗ 誤解: OCaml で書かれていたから Rust は OCaml の子

✓ 正しくは: 「実装」と「設計上の影響」は別。たまたま両方が当てはまるのが OCaml → Rust で、Rust は 2011 年に Rust 自身で書き直された（セルフホスト）。

✗ 誤解: TypeScript は JavaScript の子だから、JavaScript で書かれている

✓ 正しくは: 言語としては JS の上位互換（派生）だが、コンパイラは長く TypeScript 自身で書かれ、TypeScript 7.0（2026 年）で Go 製に置き換わった。親（派生元）と実装言語は一致しなくてよい。

✗ 誤解: 系譜は 1 本の家系図にまとまる

✓ 正しくは: 実際は複数の親を持つ網目状。図の上の方では、ALGOL が C 系と ML 系の両方の祖先になっている。
