**ざっくり言うと**

- 動的計画法 (dynamic programming) は、 **何度も出てくる部分問題の答えを表に覚えて使い回す** 方法。分割統治との違いは [設計手法の全体像](https://memo.taka1156.site/md/algorithm-paradigms.md) 。
- 決めることは 3 つ。 **状態** （ `dp[i]` が何を表すか）、 **遷移** （どの小さい答えから作るか）、 **初期値と計算の順番** 。
- 計算量はおおよそ **「状態の数 × 1 つの状態の遷移の数」** 。型（ナップサック・文字列・区間・bit など）を知っていると状態を見つけやすい。

## 組み立て方 — 状態・遷移・初期値

例: 階段を 1 段か 2 段ずつ上る。n 段目まで上る方法は何通り？

1

**状態を決める**

`dp[i]` ＝「i 段目にちょうど着く方法の数」。 **答えが表のどこかに入る** ように、しかも小さい問題から順に作れるように決める。

2

**遷移を書く**

i 段目の直前は i−1 段目か i−2 段目のどちらか。 `dp[i] = dp[i−1] + dp[i−2]` 。「最後の 1 手で場合分け」が基本の発想。

3

**初期値と順番**

`dp[0] = 1` （何もしない 1 通り）、 `dp[1] = 1` 。i の小さい順に埋めれば、使う値はいつも計算済み。答えは `dp[n]` 。

同じ問題でも状態の決め方は 1 つではない。状態が多すぎて間に合わないときは、「本当に区別する必要がある情報は何か」を考えて状態を減らす。

## 2 つの書き方 — メモ化再帰とボトムアップ

メモ化再帰（トップダウン）

ボトムアップ（表を埋める）

```
from functools import cache

@cache                      # 同じ引数の結果を覚えておく
def ways(i):
    if i <= 1:
        return 1
    return ways(i - 1) + ways(i - 2)

print(ways(50))
```

漸化式をそのまま書いて、結果を覚えるだけ。計算の順番を考えなくてよく、 **実際に必要になった状態だけ** を計算する。再帰が深くなると Python では上限（既定は 1000 段）に当たるので、 `sys.setrecursionlimit` で上げるかボトムアップに書き直す。

```
dp = [0] * (n + 2)          # n = 0 でも dp[1] に書けるよう 1 つ多めに取る
dp[0] = dp[1] = 1
for i in range(2, n + 1):   # 小さい方から順に埋める
    dp[i] = dp[i - 1] + dp[i - 2]
print(dp[n])

# 直前の 2 つしか使わないので、変数 2 つでも書ける（メモリ O(1)）
a, b = 1, 1
for _ in range(n - 1):
    a, b = b, a + b
print(b)                    # 答えは b
```

表を小さい方から埋める。関数呼び出しがない分速く、再帰の深さの心配もない。 **使い終わった行を捨てて** メモリを減らせる。ただし「どの順番なら使う値が計算済みか」を自分で決める必要がある。

## ナップサック — 表が埋まる様子

重さの上限 7 のナップサックに、品物を **それぞれ 1 個まで** 入れる。価値の合計の最大は？ 品物を 1 つずつ増やしながら、 `dp[i][w]` ＝「最初の i 個から選び、重さ合計が w 以下のときの最大価値」を埋めていく。

1 マス進む

1 行進む

全部埋める

最初から

いま計算するマス 使う値 答えをたどった道

```
# i 個目を「入れない」か「入れる」かの 2 通りを比べる
dp[i][w] = max(dp[i-1][w],                       # 入れない
               dp[i-1][w - wt[i]] + val[i])      # 入れる（w ≥ wt[i] のとき）
```

- 計算量は O(n × W) 。品物を全部の組み合わせで試す O(2ⁿ) から、表の大きさまで減った。
- ただし W（重さの上限）が 10⁹ のように大きいと表が作れない。そのときは「価値の合計 v を達成する最小の重さ」と、 **状態の軸を入れ替える** 。
- 1 次元の配列で書くときは、w を **大きい方から** 回す。小さい方から回すと、同じ行で更新したばかりの値を使ってしまい「同じ品物を何個でも入れてよい」問題（個数制限なしナップサック）の答えになる。

## 文字列の DP — 編集距離と diff

文字列 A を B に変えるのに必要な、1 文字の **挿入・削除・置換** の最小回数を **編集距離** （レーベンシュタイン距離）という。 `d[i][j]` ＝「A の先頭 i 文字を B の先頭 j 文字に変える最小回数」。

A B

```
d[i][j] = min(d[i-1][j] + 1,                         # A の i 文字目を削除（上から）
              d[i][j-1] + 1,                         # B の j 文字目を挿入（左から）
              d[i-1][j-1] + (0 if A[i]==B[j] else 1)) # 一致 or 置換（斜め）
```

- 2 つの文字列（長さ n・m）の DP は O(nm) 。 **最長共通部分列 (LCS)** も同じ形の表で解ける。
- `diff` は「2 つのファイルの行の並びの共通部分を最大にする」問題。 `git diff` が既定で使う Myers のアルゴリズムは、表を全部は埋めずに、差分が少ないほど速く終わるよう工夫した方法。
- 入力ミスの候補（「もしかして」）やあいまい検索も、編集距離が小さい語を探すことが多い。

## 典型パターン

| 型 | 状態の例 | 問題の例 | 計算量の目安 |
| --- | --- | --- | --- |
| 1 次元 | `dp[i]` : i 番目まで見たとき | 階段、最大部分配列問題（連続する区間の和の最大）、最長増加部分列 (LIS) | O(n) 〜 O(n²) （LIS は二分探索で O(n log n) ） |
| ナップサック | `dp[i][w]` : i 個目まで・重さ w | 部分和問題、予算内の最大価値 | O(nW) |
| 2 つの列 | `dp[i][j]` : A の i 文字目・B の j 文字目まで | LCS、編集距離 | O(nm) |
| 区間 | `dp[l][r]` : 区間 [l, r) をまとめたとき | 隣どうしを合体させる最小コスト、連鎖行列積（行列の掛け算の順番） | O(n³) |
| bit | `dp[S][v]` : 訪れた集合 S・今いる v | 巡回セールスマン問題（n ≤ 20 程度） | O(2ⁿ n²) |
| 桁 | `dp[桁][N より小さいと確定したか][…]` | N 以下で「各桁の和が K の倍数」の個数 | O(桁数 × 状態) |
| 木 | `dp[v][…]` : v を根とする部分木 | 部分木の大きさ、隣り合わない頂点を選ぶ最大数 | O(n) |

## DP が使える条件 — 状態のつながりがループしない

- 状態を点、「この答えからあの答えを作る」を矢印にすると、DP は **ループのない有向グラフ (DAG)** を矢印の順にたどる計算になる。ループがあると「先に計算すべきもの」が決まらない。
- 最大・最小を求める DP では、さらに **部分問題の最適解を組み合わせると全体の最適解になる** （最適部分構造）ことが前提。最短経路の一部も最短経路になる、など。
- ループがある最短経路は、DP の表を「確定した順」に埋めるダイクストラ法などで解く（ [グラフ探索と最短経路](https://memo.taka1156.site/md/graph-algorithms.md) ）。

## よくある誤解

✗ DP は表（配列）を作るもの

✓ メモ化再帰も DP。本質は「部分問題の答えを 1 回だけ計算して使い回す」こと。辞書でメモしてもよい。

✗ メモ化すればどんな再帰も速くなる

✓ 速さは状態の数で決まる。引数に「選んだものの一覧」を丸ごと入れると状態が 2ⁿ 通りになり、メモしても速くならない。状態に入れる情報を絞るのが設計の中心。

✗ 2 次元の表を 1 次元にしても、ループの向きは同じでよい

✓ 1 個までのナップサックは w を大きい方から回す。向きを間違えると、同じ品物を何度も使った答えになる。
