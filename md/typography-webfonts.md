## 文字組みの基本：サイズ・行間・行長

本文の読みやすさに効くのは、ほぼ次の 3 つ。どれも「大きすぎ・小さすぎ」の両方に失敗がある。

| 項目 | CSS | 目安（本文） | 外れたとき |
| --- | --- | --- | --- |
| 文字サイズ | `font-size` | 16px（ブラウザの既定）前後。日本語は 15〜16px | 小さいとスマホで読めない。大きすぎると 1 行の字数が減り、目の往復が増える |
| 行間 | `line-height` | 日本語 1.6〜1.8、英語 1.4〜1.6。単位なしの数値で書く | 詰まると次の行を見失う。開きすぎると段落のまとまりが崩れる |
| 行長（1 行の長さ） | `max-width` | 日本語 35〜40 字前後（30〜45 字に収める）、英語 45〜75 字 | 長いと行頭に戻るとき迷う。短いと改行だらけで読みにくい |
| 字間 | `letter-spacing` | 本文は 0〜0.05em。見出しは詰め気味 | 本文で開けすぎると単語・文節のまとまりが見えなくなる |

日本語は全角 1 字がほぼ 1em なので、 `max-width: 38em` と書けば「1 行 38 字くらい」になる。 `line-height` を `24px` のような固定値にすると、子要素の文字サイズを変えたときに行間が追従しない。

### 動かして確かめる

文字サイズ 16px 行間 1.7 1 行の字数 38 字

Web フォントは、ページで使う文字が実際に描かれるときに初めて読み込まれる。届くまでのあいだは、文字を隠して待つか、手元にある代替のフォントで先に表示しておくかを選べる。どちらを選んでも、届いた瞬間に字幅が変わると行の折り返しが変わり、読んでいた位置がずれることがある。

## font-family とフォールバック

`font-family` は「上から順に試す候補の列」。ブラウザは **1 文字ずつ** 、その文字を持っている最初のフォントで描く。和文フォントは英数字も持っているので、和文を先に書くと英数字まで和文フォントの字形になる。

```
/* 欧文フォント → 和文フォント → 総称ファミリー の順 */
font-family: "Inter", "Noto Sans JP", system-ui, sans-serif;
```

上の指定で「Web 2026 年」を描くときの選ばれ方:

**W** Inter

**e** Inter

**b** Inter

**2** Inter

**0** Inter

**年** Noto JP

Inter は漢字を持っていないので、「年」だけが次の候補の Noto Sans JP で描かれる。どの候補も持っていない文字は、最後の総称ファミリー（ `sans-serif` など）経由で OS のフォントが使われる。

| 総称ファミリー | 中身 | 使いどころ |
| --- | --- | --- |
| `sans-serif` | ゴシック体・サンセリフ | 画面の本文・UI の既定 |
| `serif` | 明朝体・セリフ | 読み物・長文。細い横線が小さいサイズでかすれないか確かめる |
| `monospace` | 等幅 | コード・桁をそろえたい数字 |
| `system-ui` | OS の UI フォント | 読み込みゼロで速い。OS ごとに見た目が変わる |

数字の桁をそろえたいだけなら、等幅フォントに変えずに `font-variant-numeric: tabular-nums` （フォントが対応していれば数字だけ等幅）で済む。和文の見出しで仮名の間が空いて見えるときは `font-feature-settings: "palt"` （プロポーショナル幅）で詰められる。

## 単位とサイズの決め方

- **rem で書く。** `1rem` はルート要素の文字サイズ（既定は 16px）。利用者がブラウザの設定で文字を大きくしたとき、rem はそれに従うが px は従わない。
- **サイズは段階（スケール）で決める。** 本文 1rem から 1.25 倍ずつ（1 → 1.25 → 1.563 → 1.953rem）のように比率を決めておくと、見出しの大小がそろう。値はデザイントークンにしておく。
- **見出しは `clamp()` で画面幅に追従させる。** `font-size: clamp(1.25rem, 4vw, 2rem)` なら、最小 1.25rem・最大 2rem のあいだで幅に比例する。最小値を rem にしておくと文字の拡大にも効く。

## Web フォントが表示されるまで

1. **HTML と CSS を読む** `@font-face` が見つかっても、この時点ではまだダウンロードしない。
2. **そのフォントで描く文字が見つかる** レイアウトの途中で「この要素はこのフォント・この文字」と決まって初めてリクエストが出る。 `unicode-range` を書いたファイルは、その範囲の文字が使われたときだけ読まれる。
3. **届くまでの見せ方を決める** ここで `font-display` の値に従い、文字を隠して待つ（ブロック）か、代替フォントで先に描く（スワップ）か決まる。
4. **届いたら描き直す** 代替フォントと字幅や高さが違うと、ここで行の折り返しが変わってレイアウトがずれる（CLS の原因）。

### font-display の 5 つの値

フォントを使い始めてからの時間を 3 つの期間に分けて考える。 **ブロック期間** は文字を見えない状態で待ち、 **スワップ期間** は代替フォントで描きつつ届いたら切り替え、 **失敗期間** に入ると届いても切り替えない。

ブロック（見えない・斜線） スワップ（代替で表示 → 届けば切替） 失敗（代替のまま）

block

約 3 秒 ずっと

swap

ずっと

fallback

約 3 秒 以後

optional

以後

0s 1s 2s 3s 4s 5s 6s

数値は CSS Fonts の仕様が勧める目安（ブロックの「ごく短い」は 100ms 以下）。 `auto` はブラウザ任せで、多くのブラウザでは `block` と同じに振る舞う。

フォントが届くまでの時間ごとに、利用者に見えるもの:

0.05 秒で届く

1.5 秒で届く

5 秒で届く

| block | ほぼすぐ Web フォントで表示 |
| --- | --- |
| swap | ブロック期間内に届くので、代替フォントを見せずに Web フォントで表示 |
| fallback | 同上 |
| optional | 同上 |

| block | 1.5 秒間、文字が見えない → Web フォントで表示 |
| --- | --- |
| swap | すぐ代替フォントで表示 → 1.5 秒で切り替え（ずれが起きうる） |
| fallback | すぐ代替フォントで表示 → スワップ期間内なので 1.5 秒で切り替え |
| optional | 代替フォントのまま。ブラウザが裏で取得を続けてキャッシュできれば、次のページからは Web フォントで表示される（取得をやめることもある） |

| block | 約 3 秒見えない → 代替フォントで表示 → 5 秒で切り替え |
| --- | --- |
| swap | すぐ代替フォントで表示 → 5 秒で切り替え（読み始めたあとにずれる） |
| fallback | すぐ代替フォントで表示。スワップ期間を過ぎたので切り替えない |
| optional | 代替フォントのまま |

**選び方:** ブランドのロゴ文字のように字形そのものが大事なら `swap` 、本文で「ずれないこと」を優先するなら `optional` か `fallback` 。 `block` は、アイコンフォントのように代替フォントで描くと意味の通らない文字が出るときに限る。

## 軽くする・ずれを抑える

| 手段 | 何をするか | 効くこと |
| --- | --- | --- |
| WOFF2 | Web 用に圧縮された形式で配る。TTF / OTF をそのまま置かない | ファイルサイズ |
| サブセット化 | 使う文字だけのファイルを作る。 `unicode-range` で範囲ごとにファイルを分ける | 日本語フォントは数千字あり、そのままだと数 MB になる。使う範囲だけ読まれる |
| 可変フォント | 太さなどの軸を 1 ファイルに持つフォント（variable font） | 太さを何種類も使うとき、ファイルを 1 つにまとめられる |
| `preload` | `<link rel="preload" as="font" type="font/woff2" crossorigin>` で早めに取りに行く | CSS を読み終える前に取得が始まる。 `crossorigin` がないと二重に取得される |
| 代替フォントの字幅合わせ | 代替フォント側の `@font-face` に `size-adjust` ・ `ascent-override` などを書く | 切り替え時の行のずれ（CLS）を小さくする |
| そもそも使わない | 本文は `system-ui` などの OS のフォントにし、Web フォントは見出しだけ | 読み込みゼロ。いちばん速い |

```
/* 代替フォントの字幅を Web フォントに近づける例（数値はフォントごとに測る） */
@font-face {
  font-family: "Inter-fallback";
  src: local("Arial");
  size-adjust: 107%;
  ascent-override: 90%;
}
body { font-family: "Inter", "Inter-fallback", sans-serif; }
```

フォントは CORS の匿名モードで取得されるので、同じオリジンでも `preload` には `crossorigin` を付ける。ブラウザの HTTP キャッシュはサイトごとに分かれているため、「ほかのサイトで読んだ Google Fonts のキャッシュが効く」ことは期待できない。

## よくある誤解

✗ 誤解: font-display: swap にすれば Web フォントの問題は全部片づく

✓ 正しくは: swap は「文字が見えない時間」をなくすだけで、届いたときの切り替えで行がずれる問題は残る。遅い回線では読み始めたあとにずれる。ずれを抑えるには代替フォントの字幅合わせや、 `optional` を検討する。

✗ 誤解: 日本語の Web フォントは、ページを開くたびに全文字のファイルを読み込む

✓ 正しくは: `unicode-range` でファイルを分けてあれば、ページで使われた文字を含むファイルだけが読まれる。Google Fonts の日本語フォントもこの方式で、多数の小さなファイルに分けて配っている。

✗ 誤解: font-family には和文フォントを先に書けばよい

✓ 正しくは: ブラウザは 1 文字ずつ「最初に持っているフォント」を使うので、和文フォントを先に書くと英数字も和文フォントの字形になる。欧文の書体を使いたいなら欧文フォントを先に書く。

✗ 誤解: px で指定すれば、どの環境でも同じ大きさで表示されて安心

✓ 正しくは: px は利用者がブラウザで設定した既定の文字サイズを無視する。文字を大きくして読んでいる人に小さい文字を押しつけることになるので、文字サイズは rem で書く。
