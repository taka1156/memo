> Linux のファイルが「名前 → inode → データ」の 3 段でできていることから、ハードリンクとシンボリックリンク、rwx と特殊ビットの判定順、umask、マウントによる 1 本のツリーまでを図と操作で整理する。

**ざっくり言うと**

- ファイルは **名前 → inode → データ** の 3 段。名前はディレクトリが持つ「名前と inode 番号の対応表」の 1 行にすぎず、権限・所有者・サイズなどは inode が持つ。
- 権限は「所有者・グループ・その他」の 3 組の rwx。カーネルは **最初に当てはまった 1 組だけ** を見る。ディレクトリの rwx はファイルとは意味が違い、ファイルを消せるかはディレクトリの w で決まる。
- ディスクが何本あっても見えるのは `/` から始まる 1 本のツリー。各ファイルシステムを途中のディレクトリに **マウント** （接ぎ木）してできている。

### ディレクトリの rwx は意味が違う

| ビット | ファイルに対して | ディレクトリに対して |
| --- | --- | --- |
| r | 中身を読める | 中にある 名前の一覧 を読める（ `ls` ） |
| w | 中身を書き換えられる | 中に 作る・消す・名前を変える （表の行を書き換える）。x も必要 |
| x | プログラムとして実行できる | 通り抜けられる 。中の名前を使って inode にたどり着ける（ `cd` ・パスの途中に使う） |

- `r` だけで `x` が無いディレクトリは、名前の一覧は見えても、中のファイルを開くことも `ls -l` で詳細を見ることもできない。逆に `x` だけなら、名前を知っているファイルは開ける（一覧は見えない）。
- **ファイルを消せるかはファイル自身ではなく、親ディレクトリの w と x で決まる** 。読み取り専用のファイルでも、ディレクトリに書ければ消せる（ `rm` は確認を出すだけ）。
- パスの途中のディレクトリ全部に `x` が要る。 `/home/u/site/index.html` が Web サーバーから読めないときは、 `namei -l` で途中のどこが閉じているかを見る。

### カーネルの判定順

0 プロセスが root（正確には `CAP_DAC_OVERRIDE` を持つ）なら、読み書きはほぼ素通り。ただし実行は、x がどこにも立っていないファイルは root でもできない。

1 プロセスの UID がファイルの所有者と同じ → **所有者の rwx だけ** を見て決める。

2 そうでなく、プロセスのグループ（補助グループを含む）にファイルのグループがある → **グループの rwx だけ** を見る。

3 どちらでもない → **その他の rwx** を見る。

「最初に当てはまった組だけ」なので、 `chmod 077 file` にすると、所有者だけが読めない（グループと他人は読める）という逆転が起きる。ACL（ `getfacl` 、 `ls -l` で末尾に `+` ）を使うと、特定のユーザーやグループを個別に追加できる。

### 特殊ビット

| ビット | ファイル | ディレクトリ | ls での表示 |
| --- | --- | --- | --- |
| setuid | 実行すると ファイルの所有者の権限 で動く（ `passwd` が root 所有の `/etc/shadow` を書ける理由）。Linux ではスクリプトには効かない | （ふつう使わない） | 所有者の x が `s` |
| setgid | 実行するとファイルのグループの権限で動く | 中に作ったファイルが ディレクトリのグループを継ぐ 。チームの共有フォルダに使う | グループの x が `s` |
| sticky | （今は意味なし） | w があっても、 自分のファイルしか消せない （ `/tmp` ） | その他の x が `t` |

x が立っていないのに特殊ビットだけ立っていると大文字（ `S` ・ `T` ）で表示される。たいてい設定ミス。

### umask: 新しく作るときの既定

プログラムは普通、ファイルを `666` 、ディレクトリを `777` で作ろうとし、そこから umask のビットを落としたものが実際の権限になる。umask はプロセスの属性で、子プロセスに引き継がれる（ [Linux プロセス](https://memo.taka1156.site/md/linux-process.md) ）。

| umask | 新しいファイル | 新しいディレクトリ | 使われ方 |
| --- | --- | --- | --- |
| 022 | 644 | 755 | システム全体や root の既定。他人も読める |
| 002 | 664 | 775 | ユーザーごとに専用グループがある環境（Ubuntu・Fedora の一般ユーザーの既定）。グループで共同編集 |
| 077 | 600 | 700 | 自分しか触れない。秘密情報を扱うスクリプト |

## マウント: 1 本のツリーへの接ぎ木

/ ← ext4 (/dev/nvme0n1p2) ├─ boot/efi ← vfat (/dev/nvme0n1p1) ├─ etc/ usr/ var/ ├─ home ← btrfs (/dev/nvme1n1) ここから下は別のディスク ├─ proc ← proc プロセスの情報をカーネルがその場で見せる ├─ sys ← sysfs デバイス・カーネルの設定 ├─ dev ← devtmpfs デバイスファイル（/dev/null, /dev/sda…） ├─ run , tmp ← tmpfs メモリ上。再起動で消える（/tmp はディストリによる） └─ mnt/nas ← nfs ネットワーク越し

- `mount /dev/sdb1 /mnt/usb` で、 `/mnt/usb` から下がそのディスクの中身に差し替わる。元の `/mnt/usb` にあったファイルは消えたのではなく、隠れて見えないだけ（外すと戻る）。
- ハードリンクや `mv` の速さは「同じマウントの中か」で決まる。 `/home` が別ディスクなら、 `/tmp` から `/home` への mv はコピーになる。
- **バインドマウント** はディレクトリを別の場所にもう 1 つ見せる（ `mount --bind` ）。Docker の `-v ./src:/app` はこれ。
- Docker のイメージのレイヤーは **overlayfs** で重ねて 1 つに見せ、コンテナごとにマウントの名前空間を分けて別の `/` を見せている（ [Docker 動作原理](https://memo.taka1156.site/md/docker.md) ）。

## よくある誤解

読み取り専用（444）のファイルは消せない

消すのはディレクトリの表から 1 行を取り除く操作なので、必要なのは親ディレクトリの w と x。ファイル自身の権限は関係ない。他人のファイルを消されたくない共有ディレクトリには sticky ビットを立てる。

大きなログを rm したのに、df の空き容量が増えない

まだそのファイルを開いているプロセスがあると、名前が消えても inode とデータは残る（ `du` には出ないが `df` には残る）。 `lsof +L1` で見つけて、そのプロセスを再起動するか、ファイルを `: > file` で空にしてから消す。

困ったら chmod 777 にすれば動く

誰でも書き換えられるファイルは、他のユーザーや侵入したプロセスが中身を差し替えられる。たいていの原因は所有者の違いかパスの途中の x 不足なので、 `namei -l` と `ls -l` で見て、所有者（ `chown` ）かグループで解決する。

ctime はファイルを作った日時

ctime は inode を最後に変えた時刻（change）。 `chmod` でも `mv` でも変わる。作成時刻が欲しいときは `stat` の Birth を見る（ファイルシステムが記録していれば出る）。

## コマンド例

```
ls -li                        # 先頭が inode 番号、権限の次がリンク数
stat memo.txt                 # inode の中身（mode・uid・3 つの時刻・Birth）
find . -samefile memo.txt     # 同じ inode を指す名前（ハードリンク）を探す
namei -l /home/u/site/index.html   # パスの途中の各ディレクトリの権限
id                            # 自分の UID と所属グループ（判定に使われる）
chmod u+x,go-w script.sh      # 記号で足し引き
chmod 2775 /srv/share && chgrp team /srv/share   # チームの共有ディレクトリ
umask                         # 今のシェルの umask
df -h; df -i                  # 容量と inode の空き
lsof +L1                      # 消されたのに開かれたままのファイル
findmnt                       # マウントのツリー（種類とオプション付き）
```
