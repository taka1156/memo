📋 Copy-on-Write (CoW) の動作
1
コンテナが /etc/nginx/nginx.conf を読む → lowerdir から透過的に参照
2
書き込み発生 → カーネルが lowerdir からファイルを upperdir にコピー
3
upperdir 上の差分のみを変更。元の lowerdir は一切変更されない
4
コンテナ削除 → upperdir だけ消去。イメージ(lowerdir)は再利用可能
# 実際のマウント確認
$ docker inspect <container> | grep -A5 GraphDriver
→ LowerDir / UpperDir / MergedDir / WorkDir が確認できる
Linux Namespaces — 隔離の種類
PID
Process ID
コンテナ内のプロセスに独立した PID 空間。コンテナの init は PID 1 に見える
NET
Network
仮想NIC・ルーティングテーブル・ポートを独立化。外部とは veth ペアで接続
MNT
Mount
マウントポイントの独立化。OverlayFS をここにマウントし専用ファイルシステムを構築
IPC
Inter-Process Comm
共有メモリ・セマフォをコンテナ間で隔離。意図しない通信を防ぐ
UTS
UNIX Timesharing
ホスト名・ドメイン名を独立化。コンテナごとに別のホスト名を設定可能
USER
User ID
コンテナ内の root をホストの非特権ユーザーにマッピング (rootless Docker)

⚡ cgroups v2 によるリソース割り当て例

cgroups はリソースを制限するだけでなく、計測・優先度付けも行う。
/sys/fs/cgroup/ 以下にファイルシステムとして公開される。
docker run の実行フロー
01
CLI → Docker Daemon
docker run コマンドを受け取った Docker CLI が Unix ソケット経由で dockerd (daemon) に REST リクエストを送る
$ docker run -it ubuntu:22.04 bash
02
イメージのプル / キャッシュ確認
ローカルに対象イメージが存在するか確認。なければ Docker Hub (Registry) からレイヤーを取得し /var/lib/docker/overlay2/ に展開
03
containerd → runc へ委譲
dockerd は containerd に指示を出し、containerd は OCI ランタイムである runc を呼び出す
04
Namespace の作成
runc が clone() システムコールで PID / NET / MNT / UTS / IPC 名前空間を新規作成し、プロセスをその中に配置
05
OverlayFS のマウント
lowerdir (イメージレイヤー群) と upperdir (書き込み用) を merged ディレクトリに OverlayFS でマウント。コンテナのルートファイルシステムとして設定
06
cgroups の設定
/sys/fs/cgroup/ にコンテナのグループを作成し、CPU・メモリ等のリソース制限を書き込む
07
pivot_root → PID 1 起動
pivot_root() で merged をルートに切り替え、Dockerfile の CMD / ENTRYPOINT を PID 1 として exec。コンテナが起動完了
→ bash プロセスが起動 (コンテナ内では PID 1)
