ざっくり言うと
  • まず入力の大きさから、使える計算量を見積もる。小さければ全探索で十分。
  • 大きいときは「問題をどう小さくするか」で手法が分かれる。その場の最善を選び続ける＝貪欲法、分けて解いて合わせる＝分割統治法、重なる部分問題の答えを覚えて使い回す＝動的計画法。
  • 「この値なら条件を満たすか」が値の大小で一方向に切り替わるなら、答えそのものを二分探索できる。

入力の大きさから計算量を見積もる

単純な処理なら 1 秒におよそ 10⁸ 回（1 億回）が目安。入力の上限 n を見れば、使える計算量の形がおおよそ決まる。

n の上限（目安）間に合う計算量よく使う手法
〜10O(n!)順列をすべて試す
〜20O(2ⁿ)・O(2ⁿ·n)部分集合をすべて試す（bit 全探索）、bit DP
〜40O(2^(n/2))半分全列挙（半分ずつ全部試して突き合わせる）
〜500O(n³)三重ループ、区間 DP、ワーシャル–フロイド法
〜5,000O(n²)二重ループ、2 次元の DP
〜10⁶O(n log n)ソート、二分探索、ヒープ、ダイクストラ法
〜10⁸O(n)1 回なめる、累積和、しゃくとり法
それ以上O(log n)・O(1)二分探索、繰り返し二乗法、式で直接求める

あくまで目安。言語（Python は C++ より数十倍遅いことがある）や、1 回の処理の重さで変わる。

全探索 — まず「全部試すといくつか」を数える

  • 候補をすべて列挙して、条件を満たすか・どれが最良かを調べる。正しさの心配がいちばん少ないので、間に合うならこれが最善。
  • bit 全探索: n 個それぞれを「選ぶ / 選ばない」の 2 通りで、全部で 2ⁿ 通り。0 から 2ⁿ−1 までの整数の各ビットを「選ぶかどうか」に対応させて回す。
  • バックトラッキング: 1 つずつ決めながら、途中で条件を破ったらそれ以上進まず戻る（枝刈り）。数独や N クイーン。最悪は全探索と同じだが、実際にはかなり減る。
  • 速い解法を書いたら、小さい入力で全探索の答えと突き合わせると、間違いを見つけやすい（ランダムテスト）。
# bit 全探索: 重さの上限 W 以内で価値の合計を最大にする（n ≤ 20 くらいまで）
best = 0
for mask in range(1 << n):          # 2^n 通り
    w = v = 0
    for i in range(n):
        if mask >> i & 1:             # i 番目を選ぶ
            w += weight[i]; v += value[i]
    if w <= W:
        best = max(best, v)

貪欲法 — その場の最善を選び続ける

毎回「今いちばん良く見えるもの」を選び、後から選び直さない。速くて書きやすいが、最適になることを示せる問題でしか正しくない。

最適になる例

区間スケジューリング: 会議室に入る予定の数を最大にするなら、終了時刻が早い順に、重ならないものを取っていく。

ほかに、ダイクストラ法・クラスカル法（グラフ）、ハフマン符号。「最適解の選択を貪欲の選択に入れ替えても悪くならない」（交換論法）で正しさを示せる。

最適にならない例

開始時刻が早い順や短い順に取ると、区間スケジューリングでも反例がある。

硬貨の枚数を最小にする問題も、硬貨の種類によっては大きい順に取ると失敗する（下で試せる）。

分割統治法 — 分けて解いて、合わせる

問題を重ならない小さな問題に分け、それぞれを（再帰的に）解き、結果を合わせる。代表はマージソート。

MERGE SORT

分けるのは log₂8 = 3 段。各段で合わせる手間は合計 n。全体で n × log n、つまり O(n log n)。

  • 計算量は「1 回で何個に分けるか・どれだけ小さくなるか・合わせる手間」で決まる。マージソートは「2 つに・半分に・n」で T(n) = 2T(n/2) + O(n) → O(n log n)（マスター定理）。
  • クイックソートも分割統治。基準値で「小さい側・大きい側」に分け、合わせる手間はほぼない代わりに、分け方が偏ると O(n²) になる。
  • 繰り返し二乗法: xⁿ = (x^(n/2))² と半分にしていき、O(log n) 回の掛け算で求める。RSA などで使う「大きな数のべき乗の余り」の計算もこの方法（暗号の基礎）。
  • 二分探索も、半分を捨てて片方だけ解く分割統治の一種と見なせる。

分割統治と動的計画法の違い — 部分問題が重なるか

フィボナッチ数 fib(n) = fib(n−1) + fib(n−2) をそのまま再帰で書くと、同じ fib(k) を何度も計算する。分けた問題同士が重なっているので、分割統治のままでは指数的に遅い。一度計算した答えを覚えておく（メモ化）と、各 fib(k) は 1 回ずつで済む。これが動的計画法。

答えで二分探索 — 「x なら間に合うか」を判定する

二分探索はソート済み配列を探すだけのものではない。「答えが x なら条件を満たすか」を判定する関数があり、x を大きくすると不可 → 可が一度だけ切り替わる（単調）なら、その境目を二分探索で探せる。

例: 重さ weights の荷物を、この順番のまま D 日以内に運びたい。1 日に積める重さの上限 W を最小でいくつにすればよいか。

W を決めれば「何日かかるか」は前から貪欲に積むだけで分かる。W を大きくするほど日数は減る（単調）ので、W を二分探索する。

def can(W):                       # 上限 W で D 日以内に運べるか
    days, load = 1, 0
    for w in weights:
        if load + w > W:          # 今日はもう積めない → 次の日へ
            days += 1; load = 0
        load += w
    return days <= D

ng, ok = max(weights) - 1, sum(weights)   # ng: 必ず不可 / ok: 必ず可
while ok - ng > 1:
    mid = (ng + ok) // 2
    if can(mid): ok = mid
    else:        ng = mid
print(ok)                         # 可になる最小の W。O(n log(合計))
  • 「ng は常に不可、ok は常に可」を保ったまま幅を縮めると、境目のずれ（±1 のバグ）を起こしにくい。
  • 実務でも同じ形がある。git bisect は「このコミットでは壊れているか」を判定しながら、壊れ始めたコミットを二分探索する（Git の内部構造）。

ほかによく使う考え方

  • しゃくとり法 (two pointers): 区間の左端と右端を前にだけ動かして、「合計が K 以下の連続部分列」などを O(n) で数える。
  • 累積和: 先頭からの合計を前もって作っておき、区間の合計を引き算 1 回で求める。
  • 半分全列挙 (meet in the middle): 2ⁿ 通りを、半分ずつの 2^(n/2) 通り × 2 に分けて突き合わせる。n ≤ 40 くらいの全探索に使う。

よくある誤解

再帰で書けば分割統治法

再帰は書き方で、分割統治は「重ならない部分に分けて合わせる」という設計。動的計画法も再帰（メモ化）で書けるし、マージソートはループでも書ける。

貪欲法は近似なので、正しい答えは出ない

最適になることを示せる問題（区間スケジューリング、ダイクストラ法、クラスカル法）では正確な答えが出る。示せないのに使うと、反例で間違う。

二分探索はソート済み配列専用

「条件が一方向に切り替わる」ものなら何でもよい。答えの値、時刻、コミットの並びなど。
