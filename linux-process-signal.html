Linux 端末・プロセス・シグナル

全体像 — キー入力と Ctrl+C がプロセスに届くまで

全体像端末とシェルプロセスシグナルとジョブ制御
ざっくり言うと
  • ターミナルは「画面とキーボード」、シェルは「コマンドを起動するプログラム」。どちらも普通のプロセスで、間をつなぐ端末デバイス（擬似端末）とラインディシプリンはカーネルの中にある。
  • プロセスは fork（自分を複製）→ exec（中身を別のプログラムに入れ替え）→ wait（親が終了を回収）で生まれて消える。
  • シグナルはカーネルがプロセスに付ける「割り込みの印」。Ctrl+C も kill も、カーネルが印を付け、プロセスが次に動くときに既定動作・ハンドラ・無視のどれかで処理される。

全体像: OS の層とシステムコール

Linux は大きくユーザー空間とカーネル空間に分かれる。アプリはハードウェアを直接触れず、必ずシステムコール (system call) でカーネルに頼む。シェルもターミナルも、ユーザー空間で動くただのプロセス。

ユーザー空間 (user space) — 普通のプロセス。互いのメモリは見えない
ターミナルエミュレータシェル (bash / zsh)ls・vim・python …sshdsystemd (PID 1)
↕ システムコール: read write fork execve wait4 kill ioctl …
カーネル (kernel) — 全プロセスの管理者。特権モードで動く
プロセス管理・スケジューラシグナル配送メモリ管理VFS・ファイルTTY / PTY・ラインディシプリンデバイスドライバネットワーク
↕ 割り込み・I/O
ハードウェア
CPUメモリディスクキーボード・画面NIC

システムコールの入口と出口は、カーネルがシグナルを処理する大事なタイミングでもある（後述）。
