Ansible 概念図

Control Node から Managed Nodes までの流れと、役割ごとのファイル名の対応

ざっくり言うと
  • Inventory（対象ホスト）と Playbook（手順）はどちらも自分で書く定義ファイル
  • Playbook は実行時に Play → Tasks → Modules へと分解される
  • Connection Plugin（SSH / WinRM）が Control Node と各サーバーをつなぐ

概念図

青＝自分で書く定義ファイル、緑＝実行時に組み立てられる処理、黄＝接続方式。破線は参照・取り込みを表す。

定義ファイル 実行時の処理単位 接続方式 破線＝参照・取り込み

役割ごとのファイル名

ファイル名はベストプラクティスとして広く使われる慣例。Play・Tasks・Modules のように独立ファイルを持たず、他ファイルの中に書くものもある。

概念種別ファイル / 場所役割
Control Node実行環境 設定 ansible.cfgrequirements.yml Ansible 自体の動作設定。requirements.yml は使う Collection / Role の一覧。
Inventory管理対象ホスト 定義 inventory/hosts.yml どのサーバーを管理するか、どのグループに属するか。
Playbook実行手順 定義 site.ymlplaybooks/web.yml 1 つ以上の Play を並べたファイル。用途別に分けるのが定番。
Play 処理 Playbook 内の - hosts: 単位 「どのホストに」「何を」するかの組。独立ファイルはない。
Tasks 処理 roles/<名前>/tasks/main.yml モジュールを 1 回呼ぶ操作の単位。上から順に実行。
HandlersTask の一種 処理 roles/<名前>/handlers/main.yml 変更があったときだけ動く Task（再起動など）。notify: から呼ぶ。
Modules 処理 ansible.builtin.*library/（自作） 実際に作業をするプログラム。通常は書かずに使うだけ。
Roles再利用単位 定義 roles/<名前>/ tasks・handlers・templates・変数をひとまとめにしたもの。
Variablesグループ/ホスト 定義 group_vars/all.ymlhost_vars/server-a.yml Inventory のグループ名・ホスト名と同名にすると自動で読み込まれる。
VariablesRole 単位 定義 roles/<名前>/defaults/main.ymlroles/<名前>/vars/main.yml defaults は上書き前提の初期値（優先度最低）。vars は固定値。
Templates / Files 定義 roles/<名前>/templates/*.j2roles/<名前>/files/ .j2 は Jinja2 テンプレート。files/ はそのまま配る静的ファイル。
Secrets 定義 group_vars/all/vault.yml ansible-vault で暗号化して保存する。
Connection Plugin 接続 ansible.cfg / ansible_connection 既定は ssh。Windows は winrm、コンテナは docker。

ディレクトリ構成例

project/
├── ansible.cfg           # 動作設定
├── inventory/
│   └── hosts.yml         # Inventory
├── group_vars/
│   ├── all.yml
│   └── web.yml
├── host_vars/
│   └── server-a.yml
├── site.yml              # Playbook（入口）
└── roles/
    └── nginx/
        ├── tasks/main.yml
        ├── handlers/main.yml
        ├── templates/nginx.conf.j2
        ├── files/
        ├── defaults/main.yml
        ├── vars/main.yml
        └── meta/main.yml
all:
  children:
    web:
      hosts:
        server-a:
          ansible_host: 192.168.10.11
        server-b:
          ansible_host: 192.168.10.12
# ↓ ここから 1 つの Play
- name: Web サーバー構築
  hosts: web          # Inventory のグループ
  become: true
  roles:
    - nginx            # roles/nginx を実行
  tasks:
    - name: パッケージ更新   # Task
      ansible.builtin.apt:  # Module
        update_cache: true

各要素の考え方

Control Node 実行する側

Ansible をインストールしてコマンドを打つマシン。管理対象側には Ansible 不要で、Linux なら SSH と Python があれば動く（エージェントレス）。Windows は WinRM と PowerShell を使い、ネットワーク機器では Python が要らないモジュールもある。

Inventory 誰に

管理するサーバーの一覧とグループ分け。Playbook 側は IP ではなくグループ名（web など）で対象を指すので、サーバーが増えても Inventory を直すだけで済む。

Playbook と Play 何を

Playbook はファイル、Play はその中の 1 ブロック。対象ごとに Play を分けて 1 つの Playbook に並べる。

Tasks と Modules どうやって

Task は「nginx をインストールする」という 1 つの操作、Module はそれを実行する部品。ほとんどのモジュールは「あるべき状態」を宣言する作りなので、何度実行しても結果が同じになる（冪等性）。ただし command / shell は任意のコマンドを実行するだけなので、creates などで条件を付けないと冪等にならない。

Roles まとめて使い回す

Playbook が長くなったら機能単位で Role に切り出す。決まったディレクトリに置くだけで tasks や templates が自動で読み込まれる。

Connection Plugin どう繋ぐか

Control Node と管理対象の間の通信方法。Ansible はモジュールを一時ファイルとして相手に送り込み、実行して結果を回収し、後片付けする。

実行の流れ

ansible-playbook -i inventory/hosts.yml site.yml を実行したときの順序。

設定を読むansible.cfg を探して読み込む。
Inventory と変数を読むホスト一覧を作り、group_vars / host_vars を紐付ける。
Playbook を解析するPlay ごとに対象ホストを決め、Roles を展開して Task 一覧を作る。
ファクト（facts）を集めるgather_facts で OS や IP などのホスト情報を取得する。
Task を順に実行するConnection Plugin で接続し、モジュールを送って実行する。
Handler を実行するchanged になった Task から notify された Handler を最後にまとめて実行。
結果を表示するPLAY RECAP でホストごとの集計が出る。
