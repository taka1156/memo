i18n と書式

Intl API・複数形・RTL ── 言語と地域が変わっても崩れない画面の作り方

ざっくり言うと
  • 国際化（i18n）は、言語や地域ごとに文言・書式・向きを差し替えられるように作っておくことで、翻訳そのもの（l10n）とは別の仕事。
  • 数値・通貨・日付・相対時間・並びの書式は自分で組み立てず Intl API に任せ、文は部品をつながずに複数形ごと 1 つのメッセージとして訳す。
  • アラビア語などの右から左の言語に備えて、CSS は左右ではなく「始まり・終わり」で書き、ロケールは URL か設定で明示的に選べるようにする。

言葉の整理

  • i18n（国際化、internationalization）: どの言語・地域にも対応できるように作っておくこと。文言をコードから外に出す、書式をロケール任せにする、など。開発者の仕事。
  • l10n（地域化、localization）: 特定の言語・地域向けに、実際に翻訳し、画像や例を合わせること。翻訳者の仕事が中心。
  • ロケール（locale）: 言語と地域などの組み合わせ。ja-JP（日本の日本語）、en-US・en-GB（同じ英語でも日付の順が違う）、zh-Hant-TW（台湾の繁体字中国語）のように、BCP 47 という形式で書く。

文字そのものの扱い（UTF-8、文字数の数え方、正規化）は 文字コードと Unicode、時刻とタイムゾーンは 日付・時刻・タイムゾーン にあります。このメモはその上に乗る、書式と文言と向きの話です。

書式は Intl に任せる

「3 桁ごとにカンマ」「年/月/日」のような書式は国ごとに違い、自分で組み立てると必ずどこかで間違えます。JavaScript の Intl は、ブラウザや Node.js に入っている各国の書式データ（Unicode の CLDR）を使って整形します。下でロケールを切り替えてみてください（表示はこのブラウザが実際に計算した結果です）。

用途結果書き方
数値NumberFormat(loc) に 1234567.891
通貨{ style: 'currency', currency: 'EUR' }
短い数{ notation: 'compact' } に 1234567
日付DateTimeFormat(loc, { dateStyle: 'long' })
相対時間RelativeTimeFormat(loc, { numeric: 'auto' }) に −1 日
並びListFormat(loc) にりんご・みかん・ぶどう（各言語の語）
期間DurationFormat(loc, { style: 'long' }) に 1 時間 30 分
複数形PluralRules(loc).select(n) の n = 0, 1, 2, 5

日付は 2026 年 11 月 14 日で固定して計算している。ヒンディー語やアラビア語では、桁の区切り方や数字の字形まで変わることがある。Intl.DurationFormat は 2025 年 3 月に主要ブラウザがそろって対応した新しい API で、古いブラウザでは結果が「（未対応）」になる。

  • 整形用のオブジェクトは使い回す: new Intl.NumberFormat(...) を作るのには手間がかかるので、表の行ごとに作らず、ロケールが決まったら 1 回作って format() を何度も呼ぶ。
  • 並べ替えも Intl で: 名前の一覧を並べるときは Intl.Collator を使う。文字コード順の sort() では、アクセント付きの文字や大文字・小文字が言語の感覚と違う順に並ぶ。
  • サーバーと結果をそろえる: サーバー側で描画して、ブラウザで同じ値を描き直すと、両者の書式データの版の違いで表示がずれることがある。ロケールとタイムゾーンを両側で明示して渡す。

文はつなげない：メッセージと複数形

t('you_have') + ' ' + count + ' ' + (count === 1 ? t('item') : t('items'))
// 英語: "You have 3 items"  日本語にすると語順が合わない: 「あなたは持っています 3 個」

語順は言語ごとに違い、部品に分けた時点で翻訳者は正しい文を作れません。「1 か、それ以外か」で単数・複数を分ける書き方も、英語でしか通用しません。

# en.json（ICU MessageFormat の書き方）
"cart": "You have {count, plural, =0 {no items} one {# item} other {# items}}"
# ja.json
"cart": "{count, plural, =0 {商品はありません} other {商品が # 個あります}}"

t('cart', { count: 3 })

文全体を 1 つの訳文にし、変わる部分（数、名前、日付）は穴として渡します。語順も複数形の分け方も、訳す人が言語に合わせて決められます。FormatJS（react-intl）や Lingui はこの形をそのまま扱え、i18next も i18next-icu プラグインを入れれば同じ書き方が使えます。

複数形の分け方は言語ごとに違う

Unicode の CLDR は、複数形を最大 6 つのカテゴリ（zero・one・two・few・many・other）で表します。どのカテゴリを使うかは言語ごとに決まっています。

日本語other
英語oneother
ロシア語onefewmanyother
アラビア語zeroonetwofewmanyother

日本語は数によって語形が変わらないので other だけ。ロシア語では 1・21・31 が one、2〜4・22〜24 が few になるなど、末尾の数字で決まる。「1st・2nd・3rd」のような順序の言い方は、new Intl.PluralRules('en', { type: 'ordinal' }) でカテゴリ（one・two・few・other）を引き、カテゴリごとに接尾辞を当てはめて作る。

  • 訳す人に文脈を渡す: 「Open」が動詞（開く）か形容詞（営業中）かは英語だけでは分からない。キーに説明を付けるか、スクリーンショットを添える。
  • 性別や敬語で変わる言語もある: ICU MessageFormat の select で、値に応じて訳文を切り替えられる。

右から左の言語（RTL）

アラビア語・ヘブライ語・ペルシア語などは右から左に書きます。<html lang="ar" dir="rtl"> にすると、文字だけでなくレイアウト全体の向きが反転するのが自然です。そのとき、CSS を「左・右」で書いていると反転しません。

dir="ltr"（日本語・英語）
A新着メッセージ 3 件›
dir="rtl"（アラビア語）
A٣ رسائل جديدة›

同じ HTML と CSS で、dir を変えただけで、アイコン・本文・矢印の並びが反転している（flex と、左右を使わない書き方のおかげ）。「›」のように Unicode で鏡像の文字が決まっている記号は、RTL では自動で向きが変わる。SVG のアイコンなど自動で反転しないものは、:dir(rtl) などで個別に反転させる。

左右で書く（反転しない）論理プロパティで書く（反転する）
margin-left・padding-rightmargin-inline-start・padding-inline-end
left: 0・right: 0inset-inline-start: 0・inset-inline-end: 0
text-align: lefttext-align: start
border-leftborder-inline-start
  • 利用者が入力した文には dir="auto": 名前やコメントなど、どの言語が来るか分からない欄は、ブラウザに中身から向きを判断させる。文の中に埋め込むなら <bdi> で囲むと、周りの文の向きを乱さない。
  • 反転させないもの: 電話番号、コード、グラフの時間軸、再生ボタンなどは、RTL でもそのままのことが多い。
  • flex や grid の並びは、dir に従って自動で反転する（CSS レイアウト）。

ロケールの決め方

  1. URL に入れる/ja/products や ja.example.com のように、URL ごとに言語を決める。検索エンジンが言語ごとのページを区別でき、リンクを共有しても同じ言語で開く。
  2. 最初の 1 回は Accept-Language で推測するブラウザが送る優先言語を見て、トップページから案内する。押し付けず、切り替えの導線を必ず置く。
  3. 選んだら覚えておくログインしていればユーザー設定に、していなければ Cookie に保存する。
  4. HTML の lang を合わせる<html lang="ja"> は、読み上げの発音、漢字の字形（日本語と中国語で同じ文字の形が違う）、ハイフネーションに効く。

IP アドレスの国から言語を決めない。旅行者、海外に住む人、複数の言語を話す国（スイス・カナダ・インドなど）で外れる。言語・書式の地域・タイムゾーン・通貨は、それぞれ別の設定として持つ。

文言の長さとレイアウト

  • 訳すと長くなる: 英語の短いラベルは、ドイツ語やフランス語に訳すと長くなりやすい。ボタンやタブの幅を文言に合わせて固定しない。
  • 画像に文字を入れない: 訳すたびに画像を作り直すことになる。文字は HTML で重ねる。
  • 疑似ローカライズ（pseudo-localization）で先に確かめる: 「Ŝàvé Çĥàñĝéš」のように文字を変えて 3〜4 割長くした仮の訳で画面を見ると、訳し忘れ（文字がそのまま残る所）とはみ出しを、翻訳の前に見つけられる。
  • フォント: 言語ごとに必要な文字が違う。Web フォントを使うなら、対応する文字の範囲を確かめ、なければシステムフォントに落ちるように並べる。

よくある誤解

言語は国で決まるので、国を選んでもらえば足りる

同じ国でも複数の言語が使われ、同じ言語でも国で書式が違う（en-US と en-GB で日付の順が逆）。言語と地域は別に持ち、BCP 47 のロケールで表す。

複数形は「1 か、それ以外か」で分ければよい

英語ではそうだが、日本語は分けず、ロシア語は 4 つ、アラビア語は 6 つに分ける。分け方は言語ごとに CLDR の規則があるので、PluralRules や MessageFormat に任せる。

訳した部品をつなげれば、どの言語の文も作れる

語順や助詞の位置が言語ごとに違うので、部品のつなぎ方を翻訳者が変えられない。文全体を 1 つのメッセージにして、変わる部分を穴として渡す。

RTL への対応は dir="rtl" を付けるだけで終わる

margin-left のように左右で書いた CSS や、絶対配置、向きに意味があるアイコンは反転しない。論理プロパティで書き、矢印などは個別に反転させる。
