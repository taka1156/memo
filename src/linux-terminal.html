登場人物: ターミナル・TTY・シェル

ターミナルエミュレータ (terminal emulator) は GUI アプリ（GNOME Terminal、iTerm2、Windows Terminal、xterm など）。仕事は 2 つだけ。

  • 押されたキーをバイト列にして PTY のマスター側へ書く（a → 0x61、Ctrl+C → 0x03、↑ → \e[A）。
  • PTY から読んだバイト列を解釈して描画する。色やカーソル移動は \e[31m のようなエスケープシーケンスで指示される。

コマンドの意味もプロセスのことも知らない。Ctrl+C でプロセスを止めているのもターミナルではない。

TTY はカーネルの「端末デバイス」。昔、物理的なテレタイプ (teletypewriter) がシリアル線でつながっていた名残の名前。

PTY（擬似端末, pseudo terminal） はソフトウェアで作る端末で、マスター（ターミナルエミュレータが持つ）とスレーブ（/dev/pts/3 など。シェルが stdin/stdout/stderr として持つ）の対になっている。スレーブ側のプログラムからは本物の端末に見える（isatty() が真）。

間に入るラインディシプリン (line discipline) が、設定（termios、コマンドなら stty）に従って次をこなす。

  • カノニカルモード: Enter まで 1 行ためる。Backspace の処理もここ。cat や read コマンドの入力で使われる（対話シェル自体は readline などで非カノニカルにして自前で行編集する）。
  • エコー: 打った文字を画面側へ送り返す（パスワード入力ではオフにされる）。
  • 特殊文字 → シグナル: Ctrl+C → SIGINT、Ctrl+Z → SIGTSTP、Ctrl+\ → SIGQUIT。
  • raw / 非カノニカルモード: vim・less・top、対話シェルの行編集（bash の readline、zsh の ZLE）などは 1 キーずつ自分で読むためにこれに切り替える。

シェル (shell) は bash・zsh・fish などの普通のプロセス。stdin（PTY スレーブ）から 1 行読み（対話時は readline などで 1 キーずつ受け取って行を組み立てる）、解釈して、コマンドを起動する。

  • 外部コマンドは fork → exec で起動し、wait で終わりを待つ（詳しく）。
  • パイプ・リダイレクトは、起動前に子のファイルディスクリプタを付け替えて実現する。
  • ジョブ制御: ジョブごとにプロセスグループを作り、どのグループを端末の「フォアグラウンド」にするかをカーネルに伝える（tcsetpgrp）。

cd が外部コマンドではなく組み込みなのは、カレントディレクトリがプロセスごとの属性だから。子プロセスで変えても親（シェル）には伝わらない。

  • SSH: 手元のターミナル → ssh クライアント → ネットワーク → サーバーの sshd が PTY マスターを持つ → スレーブにつながった bash。サーバー側ではターミナルエミュレータの代わりを sshd がしている。
  • 仮想コンソール（Ctrl+Alt+F3 など）: GUI なしで、カーネル自身が画面に文字を描く端末（/dev/tty3）。
  • 端末なし: cron や systemd のサービス、bash script.sh < in.txt のように stdin がファイルやパイプのとき。isatty() が偽になり、Ctrl+C も SIGHUP も「端末由来」では届かない。ls を ls | cat にすると色や複数列の表示が消えるのも、ls が出力先を isatty() で調べて端末でないと判断するから。

ラインディシプリンの特殊キー

stty -a で表示される設定のうち、よく効いてくるもの。キーの割り当ては stty intr ^X のように変えられる。

名前既定のキー何が起きるか
intrCtrl+Cフォアグラウンドのプロセスグループに SIGINT（isig が有効なとき）
quitCtrl+\同じく SIGQUIT（既定動作はコアダンプ）
suspCtrl+Z同じく SIGTSTP（一時停止）
eofCtrl+Dシグナルではない。カノニカルモードで、ためた文字をすぐ渡す。行が空なら read() が 0 バイトになり、読み手は入力の終わりと判断する
erase / kill / weraseBackspace / Ctrl+U / Ctrl+Wカノニカルモードでの 1 文字消去・行消去・単語消去
stop / startCtrl+S / Ctrl+Q出力の一時停止・再開（フロー制御、ixon）。画面が固まったように見えたら Ctrl+Q
lnextCtrl+V次の 1 キーを特別扱いせず、そのまま文字として渡す

対話 bash のプロンプトでは readline が端末を非カノニカルにしているので、Ctrl+U や Ctrl+W などの行編集は readline が同じキーを自前で解釈している。ただし isig は有効のままなので、プロンプトでも Ctrl+C・Ctrl+Z をシグナルに変えるのはラインディシプリンで、readline と bash はそのシグナルを受けて入力行を捨てるなどの処理をしている。

画面を動かすエスケープシーケンス

プログラムが色を付けたりカーソルを動かしたりするときは、普通の文字に混ぜて ESC（0x1b）で始まる制御用のバイト列を出力する。ターミナルエミュレータがそれを解釈して描画を変える。

printf '\e[31m赤い文字\e[0m\n'     # 31 = 文字を赤に、0 = 元に戻す
printf '\e[2J\e[H'               # 画面を消してカーソルを左上へ（clear -x とほぼ同じ。clear はスクロールバックも消す）
echo $TERM                       # 端末の種類（xterm-256color など）
infocmp | head                   # その種類で使えるシーケンスの一覧（terminfo）

同じ処理でも端末の種類によってシーケンスが違うことがあるので、プログラムは環境変数 TERM と terminfo データベースを見て出し分ける。表示が崩れたときに reset で戻るのは、端末の状態とラインディシプリンの設定を初期化し直すから。

よくある誤解

Ctrl+C はターミナルアプリがプロセスを止めている

ターミナルは 0x03 という 1 バイトを書くだけ。それを SIGINT に変えてフォアグラウンドのプロセスグループ全員に送るのはカーネルのラインディシプリン。だから SSH 越しでも、どのターミナルアプリでも同じように効く。stty intr ^X にすれば Ctrl+X が割り込みキーになる。

Ctrl+D はプロセスを終わらせるシグナル

シグナルではない。cat などカノニカルモードで読んでいるプログラムに対して行が空のときに押すと、ラインディシプリンが読み手の read() に 0 バイトを返し、プログラムが入力の終わり (EOF) と判断して自分で終わる。行の途中で押すと、それまでの文字をすぐ渡すだけ。

Ctrl+S を押したら端末が壊れて固まった

壊れていない。Ctrl+S はラインディシプリンのフロー制御で出力を一時停止しただけで、裏ではプログラムが動いている（出力が詰まると書き込みで待たされる）。Ctrl+Q で再開する。不要なら stty -ixon で無効にできる。

シェルとターミナルは同じもの

別のプログラム。ターミナル（エミュレータ）は文字を描くだけで、どのシェルが動いているかを知らない。同じターミナルで bash から zsh に切り替えたり、シェル以外のプログラム（ssh や python）を直接動かしたりできる。

コマンド例

tty                     # 今つながっている端末 → /dev/pts/3
stty -a                 # ラインディシプリンの設定（intr = ^C; icanon echo isig …）
stty -echo; read pw; stty echo   # エコーを止めて入力（read -s も同じ）
stty intr ^X            # 割り込みキーを Ctrl+X に変える
stty sane               # 設定をまともな既定値に戻す
reset                   # 表示が崩れたときに端末ごと初期化
[ -t 1 ] && echo "stdout は端末"   # シェルでの isatty()
